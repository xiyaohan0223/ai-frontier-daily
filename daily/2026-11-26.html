2Google DeepMind 上架 HFE「人类第一考」：544 题、pass^4 严判，前沿模型仅 85.6%▸
DeepMind 在 Kaggle 上线 Humanity's First Exam（HFE）：544 个文本与图像题，覆盖 20 项基础能力、编成 136 组四变体，要求同一能力连续四次都对（pass^4）才算稳定掌握，前沿模型平均仅约 85.6%，远低于人类的 96–98%。它把评测从「一次性答对」推进到「一致性/可靠性」，暴露模型在稍加扰动的同族题上会掉分。对 Agent 落地的启示很直接：demo 里答对不等于生产可用，必须以「多次一致通过率」而非「单次最高分」作为准入指标，并同步开放社区打榜（Kaggle 赛题至 12 月 15 日）。

2arXiv｜TimeTravelContainer：让运行中的 Agent 会话可「实时分叉」的沙盒运行时▸
TimeTravelContainer（TTC）提出一种无根、非特权的容器运行时，基于写时复制（copy-on-write）对正在运行的工具会话做「实时分叉」，让 Agent 能从同一状态并行探索多条路径而几乎不增加启动与内存成本（配套的 BunshinFork 机制负责重建进程树、共享内存）。它把「反事实试错 / 树搜索 / 可回滚执行」从应用层逻辑下沉为运行时原语，尤其适合高风险的工具调用（如交易、批量操作）先分叉试算再择优落地。对 Agent 架构，启示是把「分支-评估-合并」做成基础设施，而不是在 prompt 里模拟。

3arXiv｜RUIBench：换接口比换模型更有效，同一模型可从 45% 跃到 81%▸
RUIBench 提出 RUIKit，把「机器人/电脑使用接口」按 6 种动作抽象 × 2 种交互形式交叉成 12 种接口再加自由选择接口，系统做接口消融，结果显示仅仅更换接口形态就能把 Claude Code 的任务成功率从约 45% 拉到 81%，并揭示「假完成率」——Agent 自称完成但实际未达目标的比例。这说明 GUI/CUA 的瓶颈很大程度在「系统给 Agent 的抽象是否合理」，而非模型不够强。对电商自动化（后台操作、多平台铺货），应优先设计「少决策、强反馈」的工具接口，并显式度量假完成率，而不是一味换更大的模型。

4arXiv｜ShellBench：模型与 harness 谁更重要？顶尖 Agent 仅过 62.5% 日常任务▸
ShellBench 基于 OpenClaw 超 1000 万条匿名真实 Agent 交互构建 100 个「日常工作任务」，在 12 个模型 × 5 套 harness 上系统比较，结论是 harness 与模型同样决定成败：最强模型 GPT-6 Astra 仅完成 62.5%，且约 51% 的失败源于「信息遗漏」（尽管 87% 的数据其实已采集到）。它把「日常可用性」而非「基准刷分」作为评测目标，暴露了 Agent 在信息汇总、交付完整性上的系统性短板。对产品，这意味着评测必须「端到端 + 看交付物」，并把「该收集的信息是否收全、该说的有没有说」做成可自动检查的验收项。

5arXiv｜Delegent：把易子任务委派给 27B 小模型，Claude Code 编码成本降 67%▸
Delegent 提出一套多智能体 harness：让主 Agent 把容易的子任务动态委派给一个 27B 的小语言模型（SLM），在 Claude Code 上实现约 67% 的编码成本下降且不损失任务质量。其核心洞察是「大量 token 花在本可由小模型完成的简单步骤上」，通过显式路由把贵模型留给难步骤。这与今天的 Namazu/Delegent 等「小模型够用」趋势一致，为 Agent 的成本工程提供了可复用的「路由—委派—回退」骨架。对电商 Agent，可优先在翻译、抽取、规则校验等子步骤上试水委派，并保留质量回退阈值。

6arXiv｜CUA-SEE：让「任务与验证器」共同进化的自演化 CUA 评测环境▸
CUA-SEE（阿里团队）构建闭环评测环境：从 Agent 的 rollout 证据出发，共同演化「任务」与「可执行验证器」，使评测能自适应地跟踪计算机使用 Agent 的能力边界与进展，并把「测得出」与「测得准」解耦。它针对的是静态基准的两大痛点——任务很快被刷穿、验证器跟不上真实场景——用「自演化」维持评测的区分度。对 Agent 平台，这提供了一个可持续的评测范式：评测集应随模型与业务一起生长，并优先使用可执行的验证器而非人工打分，才能长期反映真实完成率。
