1DeepMind：AI Agent 数周内找到 1024-bit RSA 两处新弱点，签名伪造效率提升约 1600 倍▸
Google DeepMind 11 月 6 日公布，在密码学家 Nadia Heninger、Emmanuel Thomé 指导下，AI Agent 自主推进出两项成果：对短摘要 1024-bit RSA 的签名伪造效率约提升 1600 倍；批量分解更多 1024-bit 密钥的边际成本降低约 30 倍。现代 RSA-2048 不受这两项具体攻击影响，DeepMind 把它定位为「AI 能把多年密码分析压缩到数周」的示范。对 Agent 产品，重点不是全自动，而是把专家直觉变成可复用的搜索策略与可验证的实验回路——人类定方向、Agent 跑长程探索、验证器兜底。

2Apiiro：Claude Code「Yes, and don't ask again」把 2,539 个密钥写进 1,994 个公开仓库▸
Apiiro 11 月披露：Claude Code 的「不再询问」会把整条已批准命令——包括密码、API key、token——明文写入 .claude/settings.local.json，而该文件默认不在 .gitignore 中。扫描 104,185 份公开副本后发现 1,122 个文件含真实凭证：379 个数据库密码、23 个 AWS key、42 个 GitHub/GitLab/npm token、43 组 SSH 登录；一半暴露文件在默认分支停留至少 217 天，四次漏洞报告被机器人自动关闭。这是 Agent 权限设计的反面教材：为省一次确认，最小权限、凭证隔离与审计被同时绕过。对电商 Agent，任何写操作授权都不应以「记住整条命令」的形式落盘。

1Nature Machine Intelligence｜AI needs meaningful versioning：模型悄悄更新、版本号不变，可复现性就失效了▸
Mavroudis、Ristea、Mougan 的评论文章指出：AI 提供方频繁更新模型与系统集成，却没有对应的版本变更，导致同样的接口调用在不同时间得到不同行为，审计与复现无从谈起。文章主张「有意义的版本化」——版本号要能反映行为变化，而不只是发布批次。对 Agent 产品，这是供应链治理的最小要求：把模型指纹、提示词、工具契约与评测快照一起版本化，否则一次静默升级就可能让线上 Agent 的合规结论失效。

2arXiv｜Unsatz：不给方程形式，让 LLM Agent 自己提出 ansatz，80 个系统上最高只解出 60%▸
以往的方程发现基准通常先把变量、候选项或待修改的定律交给模型；Unsatz 反过来：每个任务是私有种子生成的小型模拟系统（ODE/PDE、离散映射、因果/静态模型、随机过程，可含隐藏状态与噪声传感器），Agent 要在预算内「买实验」、用同一建模语言写候选程序，并只在未见过的新条件、干预与更长运行上被评分。80 个系统、20 个领域，9 个模型解出 21%–60%；在 44 个系统上经典方程发现方法几乎失效，说明难点在「找结构」而非「估系数」。更强 Agent 的失败更少但不科学，且普遍「找对变量、找错相互作用」，修订时偏好降低训练误差而非提升外推。对 AI for Science，这是比「拟合 benchmark」更接近真实科研的评测；对电商预测，同样应奖励外推与干预，而不是历史拟合。

3NeurIPS 2026 RAAAI Workshop｜The Physical Cost of Context：编码 Agent 省 token 可能反而更贵▸
论文指出编码 Agent 每次调用都会重发上下文，而真实成本由调用次数与前缀复用决定：缓存运行时只预填最长缓存前缀之后的 token，因此「更短的 prompt」如果改写了缓存历史，反而更贵。作者用质量门控协议把已执行 prefill 拆成「逻辑 prompt − 复用前缀」，在 450 个 SWE-rebench V2 定位任务上比较策略：预加载 10 个检索块（Eager）把模型调用减 35.7%、GPU 能耗代理减 33.2%；而只保留最近 5 条观察（Mask-5）虽然把 prompt 体积减 33.3%，却丢掉每任务 13.59 万可复用 token，未缓存 prefill 暴涨 608.5%、能耗升 125.6%，直接不达标。结论：省成本的正确方式是缩短轨迹，而不是编辑可复用历史。对电商 Agent 的长会话与工单处理，这直接决定「记忆删什么、留什么」。

4arXiv｜KDASO：用「邻域归纳 + 轨迹对齐 + 上下文预算」让裁决技能库自演化▸
面向责任裁决（如网约车判责、法律责任认定）的可执行技能库，现有做法有三个问题：场景演化后技能过时、技能描述与专家执行逻辑有语义鸿沟、技能太多挤爆上下文。KDASO 用最近裁决数据做邻域条件归纳来更新技能，用 LLM 轨迹分析做执行对齐精修，再按上下文预算路由技能；在网约车、法律责任与逻辑推理任务上超过通用与领域基线，跨概念相似场景迁移提升 8.96%，持续优化下性能稳定。对电商 Agent，这套结构可直接用于退款、禁售、侵权、刷单等规则库：技能要能随案例演化，且「描述—执行」必须用轨迹对齐，不能只写一段更长的 prompt。

5arXiv｜BlockLock：固定批几何，让 LLM 推理在同伴变化时仍 bitwise 可复现▸
可复现推理要求同一请求不受同批次其他请求影响；已有方案要么约束所有算子（batch-invariant kernels），要么放弃共享 prefill。BlockLock 只固定「被保护请求」看到的数值路径：BlockLock-Rows 用固定宽度行并保留批解码，BlockLock-Pack 用终端锚定打包与隔离 dummy 段，再抽取该请求的 KV 做 target-only 解码。在五个稠密模型、三种单卡部署上，同伴变化时目标输出保持 bitwise 一致；等交付工作量下，BlockLock-Rows 相比 vLLM Batch-Invariant 延迟降 53.5%–55.0%、吞吐升 115.2%–122.2%，且无需自定义 kernel。对需要「同输入同输出」的 Agent 审计与回归，这是很实用的一层基础设施。
