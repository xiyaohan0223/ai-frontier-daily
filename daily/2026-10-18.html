论文精选6 条

本期论文总结 · 组会分享版

一、今日主线（为什么选这 6 篇）

  1. Agent 自主性的「刹车」问题（#2、#3、#6）：PROBE 证明可以用小模型训练「审计 Agent」多轮挖出政策违规；The Self-Improvement Problem 则从可计算性角度证明「自动门控」在无界设定下必然失灵；DropKV 从推理效率侧给自主 Agent 续航。三篇合起来回答同一个问题——当 Agent 越来越自主，兜底机制应该建在哪一层（答案是：分层，且不要迷信单一自动门控）。
  2. 多 Agent 系统的形态与副作用（#1、#4）：HTN-Orchestrate 用显式分层任务网络在五基准上稳定胜过动态派发；Nature Communications 的极化研究则揭示数千 Agent 网络交互会自发形成回音室。前者告诉我们「结构化编排值得做」，后者提醒「放开交互要小心涌现行为」。
  3. 垂直场景的可信落地（#5）：FHIR-AgentEval（Nature 子刊）在临床工作流上量化了「带规范接地的长期记忆」带来 +9.1% 成功率——记忆不是可选项，是可靠性工程的一部分。

二、每篇一句话（按阅读优先级）

  1. HTN-Orchestrate（arXiv）：显式任务分层 + 延迟分解，同底座模型下 BrowseComp 89.73%，多 Agent 编排的当前最优解之一，精读。
  2. PROBE（NeurIPS 2026）：训练 LLM 审计员以真实用户身份多轮探测 Agent 政策违规，小审计员也能挖出高产量违规，做 Agent 治理必读，精读。
  3. LLM Agent 网络极化（Nature Communications）：数千 Agent 自发形成人类式同质聚群与观点极化，多 Agent 系统的「社会性副作用」首次系统刻画，精读。
  4. The Self-Improvement Problem（arXiv）：从可计算性证明自我改进门控的不可靠边界——所有做「Agent 自优化」的人都该知道这个理论天花板，选读。
  5. FHIR-AgentEval（npj Digital Medicine）：43 个可复位任务的临床 Agent 沙盒，记忆配置 +9.1% 成功率，垂直 Agent 评测设计范本，选读。
  6. DropKV（NeurIPS 2026）：解耦残差-输出扰动的 KV-Cache 驱逐逼近最优，长上下文 Agent 的降本细节，泛读。

三、组会讨论题

  • HTN-Orchestrate 的「Planner 管层次/依赖、Orchestrator 调度叶子任务」能否直接映射到我们的电商 Agent 编排（询盘跟进、选品上新、跨平台运营）？动态派发与预定义工作流的切换边界应该由谁判断？
  • PROBE 的小审计员思路 + Self-Improvement 的「无界设定必失灵」结论放在一起看：Accio 给商家用的 Agent 是否应该内建一个独立的「审计 Agent」角色？审计信号选什么才不会被业务指标优化掉？
  • FHIR-AgentEval 里「带规范接地的长期记忆」带来 +9.1%——我们场景中的对应物是什么（商品知识、平台规则、商家偏好）？记忆的「接地」与「过期」如何工程化？
1arXiv｜HTN-Orchestrate：分层任务网络多 Agent 编排，同底座下 BrowseComp 89.73%▸
NTU 团队提出两层框架：Planner 维护子任务层次与依赖（延迟分解直到前置结果可用），本地 Orchestrator 调度 worker 执行叶子任务，结果按 AND 语义上传、失败时重建任务网。在五个基准上超过 ReAct、Agent Team 与 DeepSeek Harness。给「动态派发 vs 预定义工作流」之争提供了第三条路：显式建模层次，但把分解推迟到运行时——对复杂长链路 Agent（如跨平台店铺运营）是可直接借鉴的架构。
arXiv:2610.22195
2NeurIPS 2026｜PROBE：训练 LLM 审计员多轮探测工具型 Agent 的政策违规▸
把 Agent 审计形式化为两人马尔可夫博弈：审计员以真实用户身份与被测 Agent 多轮对话、跨工具调用挖出「能力达标但违反政策」的隐性违规（价格、隐私、确认流程等）。用 GRPO/DPO/GFlowNet 优化的审计员发现的违规广度与产量显著超过同架构 zero-shot 对手，且审计员可以远小于被测 Agent。政策合规正是电商 Agent（改价、退款、数据使用）的命门，这篇给出了可复用的训练配方。
arXiv:2610.22124
3arXiv｜The Self-Improvement Problem：自我改进的自动门控在无界设定下必然失灵▸
DFKI 团队的理论工作：把 Agent 建模为程序、「改进」定义为不可计算的语义得分后，证明任何可终止的自动门控（奖励模型/自动评审）都无法同时保证「不放行坏更新」与「不放过好更新」——自指构造可迫使任何门失败；随机化门控同样受限。只有受限设定（有界评估 + 有限提案预算）能恢复保证，且即便如此，逐轮提升的有界分数仍可能掩盖真实得分下滑。对「让 Agent 自己改自己」的技术路线是不可回避的理论边界。
