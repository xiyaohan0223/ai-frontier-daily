本期论文总结 · 组会分享版

一、今日主线（为什么选这 5 篇）

  1. 执行前治理（#1、#2、#3）：三篇从不同层回答同一个问题——模型有能力做，系统凭什么在此刻放行？#1 用本体与任务状态给出 ready/waiting/forbidden 三种确定性裁决；#2 把宿主掌握的「工具此刻健不健康」变成执行前输入；#3 给复核者的替换权加一道证据门槛。共同点是把权限与证据从 prompt 里拿出来，放到可验证的系统层。
  2. 从单一答案到过程与集合（#4）：FoldScape 把蛋白结构预测从「一个天然态结构」扩展到整条折叠轨迹，AI for Science 的交付物正在从结构变成可采样的构象分布。
  3. 多 Agent 的求助时机（#5）：真正决定效果的不是 Agent 数量，而是谁在什么时刻发现缺口、触发检索或专家招募。

二、每篇一句话（按阅读优先级）

  1. Agent Harness Awareness（arXiv）：宿主在关键动作前注入已验证的工具健康状态，策略后悔降 96.9%、单次派发完成率 69.4%→95.8%，最接近可落地的 Agent runtime 改造，精读。
  2. SecureGARD（arXiv）：动态本体 + 回合状态做确定性门控，三个注入基准 ASR 为 0%，并给出「等待」这一比拒绝更业务友好的状态，精读。
  3. Who May Overrule the Agent?（arXiv）：证据门槛能减少 reviewer 改坏正确决策，但效果依赖模型与接口，说明「复核权限」本身需要设计，选读。
  4. FoldScape（arXiv）：用约 100 万构象覆盖未折叠—中间态—天然态，构象空间覆盖度远超 AlphaFold 3 集成，AI4S 的新范式，选读。
  5. Challenge-Aware Knowledge Recruitment（arXiv）：Challenger 触发的中途检索/专家招募在 8/9 数据集有效，简单叠加会反噬，适合作为多 Agent 编排的参照，泛读。

三、组会讨论题

  • 如果把 #2 的「工具健康快照」用到下单链路，库存、价格、支付、物流四类状态各自由谁签发、TTL 多长、过期后 Agent 应等待还是重试？
  • #3 的证据门槛如何产品化为「审批规则引擎」：价格下限、库存阈值、禁售清单哪些算 binding constraint？怎样避免 Mistral 式「把正确提案全部替换」？
  • #5 的 Challenger 角色在电商客服里应由独立小模型、规则引擎还是人承担？当检索与专家招募同时可用时，如何排序以避免 1+1<1？
1arXiv｜SecureGARD：用动态本体给工具调用做「放行 / 等待 / 禁止」裁决▸
11 月 4 日提交。针对间接提示注入，作者不再只约束工具或轨迹，而是把异构工具调用落到共享语义表示上，用可执行本体加回合级任务状态推导三种确定性决策：ready、waiting、forbidden；waiting 表示存在可恢复的未满足义务，允许在不扩大授权范围的前提下有界重规划。本体从经过验证的执行轨迹离线演化，新公理必须修复训练失败暴露的错误、保持逻辑一致，并通过留出验证。在 AgentDojo、ASB、AgentDyn 三个基准的良性与注入设置下，攻击成功率 0%，且任务效用优于基线。对电商 Agent，「等待」比「拒绝」更符合业务：缺收货地址、缺税号时应暂停并追问，而不是直接失败或越权代填。

2arXiv｜Agent Harness Awareness：把工具健康遥测变成执行前决策▸
工具描述只告诉 Agent「这个动作能做什么」，却不告诉它「此刻做是否健康」；监控、trace 与近期失败掌握在执行宿主手里，选动作的模型却是盲的。作者提出「信任分离」的设计：宿主在关键动作前提供一份小而新的已验证状态快照，同时保留测量、执行与最终派发权。在 216 次决策的消融中（GPT-5.6 Sol、Claude Sonnet 5、Gemini 3.7 Flash），工具健康状态把平均可观测策略后悔降低 96.9%（4,252ms→131ms），单次派发完成率从 69.4% 升到 95.8%；带真实 TCP/HTTP 与故障注入的 27 次复现中，9/9 个模型×故障组合完成动作，对照组仅 5/9。对下单 Agent，库存、价格、支付通道与物流 API 的健康状态应在调用前注入，而不是失败后重试。

3arXiv｜Who May Overrule the Agent？给复核者设一道「证据门槛」▸
多 Agent 系统常加一个 reviewer 来纠错，但 reviewer 也会把本来正确的决策改坏。作者把它定义为「制度管辖权」问题：在提案、任务信息、模型与复核输出都相同的条件下，reviewer 何时有权让自己的建议生效？他们比较了宽泛覆盖权与「证据门槛」——只有当 reviewer 给出机器可验证的约束违反记录与合规修复方案时才允许替换。96 个空间政策任务与 96 个组合迁移任务显示，门槛显著减少对正确提案的破坏，同时保留大部分违规修复；但在前瞻验证中，Qwen 能完全避免改坏，Mistral 仍替换了全部 48 个正确提案。结论不是「限制复核一定更好」，而是复核能力、动作接口与约束权限共同决定纠错域与破坏面。对电商审批流，人工或上级 Agent 的「一票否决」必须绑定具体规则与证据，否则只是把模型错误换成流程错误。

4arXiv｜FoldScape：从序列生成任意折叠阶段的蛋白构象集合▸
11 月 3 日提交、4 日更新。现有结构预测大多只给天然态，未折叠态与折叠中间态难以获得；FoldScape 用约 1 万个序列、100 万个构象（粗粒化折叠 + 全原子力学拉伸轨迹）训练，以折叠分数 Q 为条件，通过层次滑窗距离回归、链级组装与 rectified-flow 解码，直接生成从伸展到天然态的三维 Cα 结构，推理时不需要针对每个蛋白跑分子动力学。匹配样本比较中，它在回转半径、Q、二级结构比例上的构象空间覆盖中位数分别为 0.989/0.722/0.877，AlphaFold 3 集成仅为 0.05/0.05/0.10。对 AI for Science，这是从「预测一个答案」到「给出可采样的过程」；对药物与材料 Agent，构象集合比单一结构更适合判断结合与聚集风险。

5arXiv｜Challenge-Aware Knowledge Recruitment：多 Agent 该在什么时候求助▸
医疗问答里，多 Agent 辩论常打不过强单模型。作者认为问题出在「选专家与检索知识只看题目」：他们加入一个外部 CHALLENGER，实时检查推理轨迹，指出具体的事实或专业缺口，再触发定向检索或中途招募专家。在 MEDAGENTSBENCH 困难子集（9 个生物医学数据集、862 题）上，开场就检索几乎没有收益，而「推理中途按缺口检索」在 9 个数据集中 8 个提升，比仅用 Challenger 高 6 个百分点；招募专家由 Challenger 触发时，GPT-4.1-mini 的 MedQA 从 46% 升到 54%，自触发则不可靠；把检索与招募简单叠加反而变差。对电商客服，这意味着不是「多挂几个专家 Agent」就好，而要有一个独立角色判断「现在缺的是关税知识、物流时效还是平台规则」，再决定是否转人工或调工具。
