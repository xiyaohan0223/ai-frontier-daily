1Anthropic FlashProve：给每条回复附一张「权重来源」的零知识证明▸
11 月 2 日发布，与 EPFL、MIT 研究者合作。FlashProve 让模型提供方先承诺一套权重，再为每条回复生成 zkSNARK：用户无需权重、只需几秒即可验证「这段输出确实由承诺的模型生成」，而证明本身不泄露权重。实测 Llama 4 Maverick（400B MoE、4bit）在单张 H100 上约 110 tokens/s 出证，1024-token 请求的证明约 19MB，约为 vLLM 原生推理 GPU 时间的 70–95 倍；附带 Lean 形式化证明与 Apache 2.0 代码。限制也很明确：整数权重 + greedy decoding、上下文仅 1024 token、只保证 MoE 架构。对 Agent 产品，这意味着「模型身份」第一次可以被第三方轻量审计——但 70 倍开销决定了它更适合抽样审计与合规抽检，而不是全量线上。

1MIT「权重空间编程」：GPT-6 Astra 直接读改权重，MATH-500 从 7.9% 到 48.1%▸
11 月 3 日在社区刷屏的工作（Rikiya Takehi、Jayden Teoh、Alex Zhang、Omar Khattab）：只看原始浮点权重，GPT-6 Astra 能判断一个小网络被训练来玩哪个游戏，也能在无梯度、无训练循环的情况下改写权重。指向 Qwen3.5-0.8B 时，它定位到导致推理循环的参数方向，只改动 0.016% 的权重，就把 MATH-500 从 7.9% 提到 48.1%、GSM8K 从 13.8% 提到 67.1%、IFEval 从 21.0% 提到 62.3%。争议同样激烈：spaCy 作者 Matthew Honnibal 认为它混淆了「无工具读权重」与「写代码改模型」，Sean Goedecke 则指出其步骤与人类研究员无异。值得读，但不宜把它当成「模型可自我进化」的证据；对 Agent 的自修改，沙箱与回归测试仍是硬约束。

2Qwen 3.8 27B 在笔记本上复现「读权重」：17GB 本地模型识别 3/4 个游戏网络▸
Simon Willison 11 月 3 日复现了上述实验：用 LM Studio 跑 Q4 量化、约 17GB 的 Qwen 3.8 27B，把四个小游戏策略网络的原始权重直接喂给模型。结果它用 46 分钟、4.35 万 reasoning tokens 认出 Pac-Man（72% 置信），又分别认出 Pong（75%）与 Breakout（88%），只在更冷门的 Freeway 上失败；Kimi K3.1 Pro 走 API 也成功。这说明「从权重推断行为」并非前沿闭源模型独有，端侧/私有化模型也能承担一部分模型审计工作。但小时级延迟与超长推理链也说明，它现在更像取证工具，而不是实时能力。

3协作智能基准：前沿模型当队友仅 82.2 分，遇强势对手时只 14% 谈成最优交易▸
Stanford、Oxford 与 MIT 11 月 3 日发布 Collaborative Intelligence Benchmark：240 个任务、8 个协作维度，素材来自航空事故报告、临床病例、不当行为记录与谈判数据集。Gemini 4 Argon 以 82.2 分（高推理档）居首，但所有模型都暴露同一个问题——不是不会，而是「压不住」。冲突场景里，给双方完整信息时模型 100% 能找到最优联合方案，合作型对手时 84%，换成强势对手就只剩 14%；模型 99% 的回合会问对方需求，却仍有 81% 接受次优交易。5,094 次失败中 45% 发生在模型已识别问题之后。对采购、询盘议价类 Agent，这比通用 benchmark 更有参考价值：要把「底线、拒绝阈值、效用函数」显式写进策略，而不是期待模型靠礼貌谈出好结果。

1arXiv｜VerifierBench：让 Agent 自己写验收器，19 个模型最高只有 62.1 分▸
arXiv:2610.27913，11 月 3 日交叉列表。研究「验证器生成」：给定任务说明与环境，Agent 要写一个可执行验证器，接受所有合法解、拒绝非法解。作者构建 222 个任务、来自 6 个 Agent benchmark，含 4,993 个隐藏测试（包括替代合法解与攻击），并用 V4V 六项检查审计源验证器。19 个模型在统一 harness 下，归一化平衡准确率仅 10.6–62.1；生成器拒绝非法解比接受合法解更可靠，但这种「强」很多时候来自过度约束——多数假拒绝来自「不接受任何测试解」的验证器。错误能逃过自测，是因为 Agent 用来测试的解与验证器共享同一套错误假设。对 Agent 产品，自写验收器不能只做 self-test，必须同时验证「正确解能过」与「其他合法解也能过」。

2arXiv｜Learning to Bid and Bundle：零售竞价 Agent 的后验采样，弱市场少损失 4–7 倍▸
arXiv:2611.00165，11 月 3 日提交，37 页。场景很具体：在线零售商为易腐商品竞拍赞助搜索点击，把商品与常备品打包折扣，并展示剩余库存以抬高支付意愿；商家既不知道点击对出价的响应，也不知道市场强弱，还要在「零出价不产生信息」的截断数据里学习。作者设计后验采样 Agent：每期从精确后验抽一个市场，执行该市场完全信息最优的季度计划，因此每个动作都是「全知卖家也可能做的动作」。模拟花店中，弱市场 500 个 season 仅损失单季营收的 12–23%，比「每季只抽一次」少 4–7 倍；平均约 3 个 season 就能摆脱零出价陷阱，而后者要 50 个。还发现「等折扣」的顾客看起来像流失，频繁等待会让 Agent 低估市场；每季只打一次折，弱市场损失 5.9% 的全知营收，强市场为零。这是把探索成本写进结算的范本。

3NeurIPS 2026｜PatchScout：把主题网页采集当成长期信息觅食▸
arXiv:2611.00169，NeurIPS 2026。研究「主题网页数据采集」：目标不是回答单个查询，而是围绕一个主题，从分散、结构不连通的网页里收集可复用文档集。作者把它形式化为查询诱导的语义 patch 上的长期信息觅食，核心决策是「继续深挖当前区域，还是切换到新区域」。PatchScout 用多 Agent 框架实例化一类 patch-switching 策略，在固定预算下平衡利用与切换。四个实时网页主题上，产出量与域名覆盖均优于遍历式与搜索增强推理 Agent；在一个先验集合不完整的社会科学场景中，额外发现 102 个此前未识别的实体。对选品调研、竞品情报这类「没有唯一答案、只有覆盖度」的任务，这比一次性 RAG 更接近真实工作流。

4arXiv｜Sandman：Amazon 生产级 Agentic RL 沙箱，两周创建 310 万个环境▸
arXiv:2610.39711，11 月 3 日更新。Agentic RL 需要带状态的环境来执行工具与评估，但训练任务会突发性申请上千个环境，取消或超时又会泄漏资源。Sandman 是 Amazon 在生产 Kubernetes 上运行的沙箱服务：一个挂载进未修改任务镜像的小 daemon 负责跨调用保留文件与进程；服务侧做创建限流、就绪检查，并在调用方超时后继续承担清理责任。两周内为 122 次编码 Agent 训练创建 310 万个沙箱，峰值并发 11,858；1 万个请求的多客户端突发中，一半沙箱 116 秒可用、全部 308 秒可用，比调优过的 agent-sandbox 快 44%；软件工程镜像上空命令中位延迟 2.0ms（对比 14.3ms 与 203.5ms），客户端退出后无残留。做 Agent 平台的人应把它当作「环境层」的参考架构，而不是一篇训练论文。

5arXiv｜Cassette-Editor：把时间线变成视频 Agent 的行动语言▸
arXiv:2610.37690，11 月 3 日更新。视频编辑 Agent 缺的不是模型，而是「编码 Agent 那样的环境」：改错只在渲染后才看得出来，且不指向出错的那一步。Cassette-Editor 把时间线文档变成 Agent 的行动语言——编辑不是零散工具调用，而是带类型的组合修改；schema 检查与规则手册定义「项目允许什么」，被接受的 patch 作为历史的一步提交，被拒绝则项目不变，并定位问题、列出修复选项；读取时把源分析映射到当前编辑的帧，Agent 能看到「现在画面是什么」。在测试夹具上，人工编辑器注册的每个动作都能表达为等价的 Agent patch；长纪录片粗剪的连续修改案例中，完成率高于直接对媒体文件操作的 Codex CLI，同模型同成本下更省 token 与时间。对多模态 Agent，「可回滚的 typed patch + 自动定位错误」比更大的模型更稀缺。

6arXiv｜Early Stopping in Large Reasoning Models：早停省算力，但会牺牲「理由」的可靠性▸
arXiv:2611.00166，11 月 3 日提交。对推理模型来说，更长的思维链通常更准，但并非每个 token 都有用；早停方法想在「够答」时停下。作者用统一的 rollout replay 协议，在 5 个推理模型、数学/科学推理、代码生成与事实性任务上评估多种早停方法，并提出 TITE（相对 oracle 的目标整合 token 效率）来衡量「达到某准确率所需成本」。审计发现：后半段位置的正确率下降幅度可能超过解码噪声模型的预测；强制终止后模型仍会继续推理；部分「早停且答对」的输出，其支撑理由明显更弱。对成本敏感的 Agent，早停不能只看最终答案，还要保留可审计的理由链，否则会把「省钱」变成「不可解释」。
