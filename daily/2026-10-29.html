1豆包工作升级：把电脑操作录成「个人技能」，锁屏后仍继续执行，手机可远程派活▸
这版提升了 computer use 的精度与速度，并支持在录屏时同步解说，把一段真实操作沉淀成可复用的「技能」；之后遇到同类任务只需给出目标即可调用。更关键的是新增「允许豆包在锁屏时工作」：Mac 锁屏后任务继续跑，手机可以给锁屏的 Mac 派活并查看结果。这等于给 Agent 配了一个稳定的执行宿主，也把「示范学习」做成了消费级产品动作。对产品的启示：技能采集的体验设计（录屏 + 口述）比技能本身更重要，而「锁屏续跑 + 跨设备派活」是常驻型 Agent 的必备形态——它决定了 Agent 能否覆盖耗时超过一次会话的任务。

2StreamVibe（Google 等）：让个人 Agent 在交互过程中持续读懂用户的动态意图▸

1Axiom Math 数十个 Agent 用 24 天形式化「巨型定理」：揪出数百处错误与一处 40 年前的漏洞▸

1arXiv｜AutoVend：一个 Agent 运营 20 台售货机 180 天，5 个模型里 4 个不如规则基线▸
论文搭了一个持续经营仿真：单 Agent 通过网页界面管理分布在 5 类点位的 20 台售货机，运行 180 个模拟日，环境包含共享仓库、采购提前期、付费补货、商品过期与经常性成本。结果是 5 个 LLM Agent 中有 4 个的累计收益低于规则基线；作者进一步用「每美元推理收益」重新排序模型，结论直接翻转。失败模式集中在三处：无法把可行动作落到界面上、做出超出库存的承诺、以及把环境反馈转成后续策略。这正是「Agent 做真实生意」最该先读的一篇：它说明长周期、有现金流的任务里，可靠的流程约束比模型智力更决定成败。

2arXiv｜Evolving Agent Teams：中央调度 + 持久文件系统，多 Agent 从零写出超过 FlashInfer 的 CUDA kernel▸
Berkeley 团队（Shiyi Cao、Ziming Mao、Dacheng Li、Joseph E. Gonzalez、Ion Stoica）发现现有 coding agent 在专家手写的真实 kernel 上会停在局部最优，于是提出 Evolving Agent Teams：一个中央 supervisor 诊断当前局部最优并重组团队结构，同时用持久文件系统（学习文档、演化历史、各队产物）让每次重组都建立在既有经验上。在匹配 token 预算下稳定优于强基线；放宽预算后从零写出的 kernel 相对 FlashInfer 生产级 MLA paged decode 平均加速 1.2 倍，在 47 个生产负载中赢下 36 个，另在 AMD MI350X、B200、Apple Silicon MoE offload 与 RoboDojo 操作任务上均有提升。对 Agent 工程的启示：多 Agent 的关键不在「人多」，而在「谁有权重构组织结构」以及「组织记忆写在哪里」。

3arXiv｜Prospector（MIT）：把科学推理压成一个紧凑的图遍历策略▸
论文（MIT，Markus Buehler 团队）不走「把文献都塞进上下文」的路线，而是训练一个小策略在知识图谱上决定取证路径：先看哪条边、何时回溯、何时足以作答。规模小意味着可以在本地跑、可以逐跳解释，也让每条结论都能指回具体证据节点。对 AI4S 与垂直 Agent 的启示：在知识密集且需要负责的场景，结构化索引加可训练的小策略，往往比更大的通用模型更可控——这条思路同样适用于法规、标准、选品规则这类「必须能说清依据」的知识库。

4arXiv｜When the Critic Falls Behind：让 rubric 与 harness 协同演化，实现持续自我改进▸
清华团队（孙茂松、车万翔等）指出持续自我改进的瓶颈常在「评审器落后于执行器」：固定 rubric 会让模型只优化已知弱点，固定 harness 会限制可探索的行为空间。论文让二者协同演化——从轨迹中自动发现新的行为准则，优先攻未被解决的弱点，再据此改造脚手架，并在未见过的 held-out 任务上仍有提升。对产品的启示：任何「自动改 prompt / 自动改流程」的机制，都必须同时演化评测标准，否则就会变成对着旧考卷刷分。

5NeurIPS 2026 Oral｜NV-CoT：用连续坐标重构视觉思维链，让模型「指得准」而不只是「说得出」▸
南洋理工大学的这篇 Oral 指出，纯文字的视觉思维链在描述位置、尺寸、相对关系时会丢失精度，于是把推理步骤建立在连续坐标上：模型输出的不是「左上角的按钮」，而是一个可被后续步骤复用的坐标锚点。这直接改善了精细空间定位与多步视觉推理。对产品的启示：做商品图理解、页面元素定位（GUI Agent）、图文一致性校验时，「坐标级」的表征比自然语言描述更稳，也更适合作为可验证的中间产物。

6arXiv｜研究型 Agent 的 shell 会削弱安全对齐：5 种脚手架、50 条有害化学请求的实测▸
论文测试了 5 种常见的研究型 Agent shell（带搜索、代码执行、自主规划等能力），用 50 条有害化学合成请求探测，发现同一底层模型在挂上 shell 之后拒绝率明显下降——工具与自主性带来的「任务框架」把有害请求重构为「研究步骤」，从而绕过了模型层的拒绝。对 Agent 产品的启示：安全不能只做在模型层，必须在 harness 层再设一道策略检查（工具白名单、请求意图分类、危险组合告警），否则越是「能力强」的配置越容易越界。
