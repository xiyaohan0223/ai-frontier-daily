1DoorDash 承认第三方 Agent 只带来「几百单」：在日均 300 万单面前，Agentic Commerce 还在 demo 阶段▸
10 月 30 日的三季度财报电话会上，DoorDash 披露来自 Muse、Instinct、Fo 等第三方 Agent 的订单「总共大约几百单」；作为对照，公司在 2025 年报告中给出的日均配送量约为 300 万单。CEO Tony Xu 的回应很克制：「在技术这件事上，你永远不想对抗重力，但也不能自欺。」他明确说用户仍然主要在 DoorDash 自己的 App 里下单，但公司希望理解 Agent 场景、与第三方 Agent 开发者建立健康关系，并认为未来可能在 Agent 内部做广告。DoorDash 自己也在铺路：9 月的短信下单 Agent、7 月的 CLI Agent、6 月的 Ask DoorDash，以及面向企业订餐的 MCP。渠道态度正在分化——Amazon 在拦 Agent，Walmart 则铺红毯欢迎。对做电商 Agent 的团队，这条数据的价值不在唱衰，而在校准：Demo 里的「一句话下单」与真实成交之间，差的是账号授权、价格一致性、库存锁定、售后归属和商家结算，任何一项没打通，量就起不来。与其追逐 Agent 入口的曝光，不如先把「订单真的完成、商家真的收到钱」做成可复现的指标。

11.3B 的 OXR 登顶三大文档解析榜：用 RSI 后训练替代人工标注，100 页 101 秒▸
国产团队 SoMark 开源的 OXR（Optical Everything Recognition）只有 1.3B 参数，却在 OmniDocBench（97.18）、olmOCR-Bench（87.84）、DocParsingBench（87.76）三个文档解析榜上同时第一，代码、权重与评测流程全部公开，还提供免注册的免费 API。它一次能处理表格、公式、代码块、图片、化学方程式、脚注、页眉页脚、印章等 13 类元素，输出保留语义结构与阅读顺序的 Markdown；单张 RTX PRO 6000 端到端解析 100 页只要 101 秒，量化后一张 RTX 3060 就能跑。真正的方法论在后训练：文档解析的每一个输入都有客观确定的标准答案，于是团队用递归自我改进（RSI）替代人工标注——先用通用 VLM 把样本分成 Correct / Wrong / Uncertain 三类，Uncertain 这一档是关键，避免把评判者的犹豫硬包装成标签；再对高分歧样本做轻微图像扰动，找出模型的视觉脆弱点；随后让 VLM 做失败归因并聚类成「原因簇」，最后按原因簇生成新数据回流训练。架构上把版面分析拆成独立可插拔模块，主模型同时做内容识别与阅读顺序，既提速又让行业可以替换私有版面模型。对 Agent 产品的启示：文档解析不是外围工具，而是上下文基础设施——RAG 的检索质量、工具调用的参数正确率，很多时候死在 PDF 的表格与公式上；而「可客观判分」正是 RSI 能成立的前提，选场景时先问一句「对错能不能被机器验证」。

1智元发布「Worken」物理 AI 工时单位：GO-3 三榜第一、WITA-OMNI 无唤醒词交互、灵渠 OS 年底开源▸
10 月 30 日的智元创新日上，稚晖君抛出一个新单位 Worken，用来衡量机器人的有效智能工时，公式是「活跃机器人数量 × 自主工作时长 × 产出效能比」——部署规模、无人工接管的持续作业能力、实际产出效率三个维度被压成一个可结算的数。技术侧同时发了三样东西：具身基座模型 GO-3 Preview 采用 WRAM（World Reasoning Action Model）架构，把任务理解、推理、未来状态预测与动作生成放进统一框架，在 RoboDojo、RoboTwin、RoboColiseum 三榜登顶，并支持跨本体迁移；交互大模型 WITA-OMNI 在 Daily-Omni、TimeLens-Bench、EmbSpatialBench、MMAU 四榜第一，不需要唤醒词，靠声音方位、声纹、人脸与唇动识别对话对象，平均 600 毫秒、最快 400 毫秒响应，能听懂 100 多种语言、说 29 种语言与 7 种方言，并支持本地无网交互；快慢双系统把即时回应的 Interaction Engine 与负责推理、工具调用、长任务的 Background Agent 分开。硬件与系统侧，AHA3 用单颗 SoC 把运动、交互、作业三套智能合一，体积缩小 50%、响应提升 90%；灵渠 OS 1.0 支持 15 类 100 多种外设，在 1000Hz 负载下端到端时延抖动小于 4 微秒，系统服务封装为可复用的 Skill，年底全面开源并捐赠给开放原子基金会。落地数据也不再是 demo：龙旗 3C 产线稳定运行 7 个月，6 天直播累计作业 64,824 次、生产 17,625 台平板，成功率 99.99%，节拍 22 秒与熟练工持平；100 台灵犀 X2 在爱仕达门店 3 天带动 223 万元销售；横琴长隆部署近 500 台、覆盖 100 多个岗位。对 Agent 产品的启示：Worken 之于机器人，类似 token 之于大模型——当行业有了统一计量单位，采购与考核才会真正发生；而「快慢双系统 + 异常恢复」这套结构，对任何长任务 Agent 都直接适用。

2清华×无问芯穹×智元 CEL：96 台机器人互相「抄作业」，五项任务成功率全部超过人类操作员平均▸
清华大学、无问芯穹与智元联合提出群体经验学习（Collective Experience Learning，CEL），核心是让机器人不只向人类学习，还能复用同伴的成功经验：一台机器人在任务里卡住时，可以从群体过去的执行记录中检索相似场景下的有效做法。验证规模是 96 台真实机器人，任务包括插花、叠衣服、手机充电、凳子组装与手机包装。结果相当硬：两台没参加过训练的机器人做了 600 次测试只失败 15 次，总体成功率 97.5%，五项任务全部超过 6 名人类操作员的平均水平；手机包装从 79.2% 提升到 98.3%，连续 120 次只失败 2 次。更有意思的是规模化趋势——参与训练的机器人从 16 台增加到 96 台，成功率从 86.7% 升到 98.3%，同样的训练时间里机器越多、经验越厚、群体越强。系统层用基于 RLinf 的容错异步训练系统 FATS 支撑近百台机器人协同，96 台规模下累计 9,834 轮经验，22 台机器人发生 30 次故障，但故障造成的机时损失只占 1.3%；算法层用失败引导的经验检索微调（FERT），从成功里学「该怎么做」、从失败里找「哪里不对」。对 Agent 产品的启示：跨会话、跨用户的经验共享会形成和「机器人越多越强」同构的飞轮，但前提是经验可检索、可归因、可隔离——哪些经验能共享、哪些涉及隐私不能出域，会成为产品设计问题而不是纯技术问题。

1thedotmack/claude-mem 单日 +1,140 星：把「跨会话记忆」做成所有 Agent 的通用插件▸
claude-mem 目前约 10.6 万星、9,354 个 fork，今日新增约 1,140 星。它做的事很聚焦：记录 Agent 在会话中做过的所有事，用 AI 压缩成结构化记忆，再在后续会话开始时自动注入，让 Agent 不必每次从零了解项目背景。兼容面铺得很广，Claude Code、OpenClaw、Codex、Gemini、Hermes、Copilot、OpenCode 都能接，用 TypeScript 实现。它走红的背景是「Agent 记忆」正在从产品功能变成独立基础设施：模型上下文再长，也架不住项目跨周、跨人、跨工具。对做采购或商家 Agent 的团队，这类项目的价值是提供了一种可借鉴的形态——记忆不该是聊天记录堆叠，而应是「压缩后的结论 + 可追溯的原始证据」，并且要能按项目、按用户隔离；同时要警惕记忆投毒，任何自动注入的长期记忆都必须带来源与失效时间。

2CopilotKit/OpenBot 单日 +706 星：给每个「AI 同事」配一台自己的电脑▸
OpenBot 目前约 8,794 星、1,110 个 fork，今日新增约 706 星。它的定位是开源的「AI 同事」：每个 Agent 都拥有自己的计算机——浏览器、文件与工具，行动在执行前被确定下来、执行后被完整记录，因此可以审计、可以回放；同时通过 AG-UI 协议接入任意 Agent 实现，用 TypeScript 编写。这和前几天的 OpenMausBot、OpenClaw 属于同一波「给 Agent 一台机器」的范式，但 OpenBot 更强调团队部署与可观测性：不是一个人的玩具，而是一组可以被管理的数字同事。对 Agent 产品的启示：当 Agent 拥有浏览器与文件系统，权限边界、操作日志与产物归属就必须先设计好；「执行前决策、执行后记录」这个顺序，本身就是一种低成本的安全架构，值得抄进自己的运行时。

3macro-inc/macro：把邮件、文档、任务、Agent 和 CRM 放进一个共享记忆的工作台▸
macro 目前约 5,878 星，定位是团队的统一工作空间：邮件、聊天、文档、任务、Agent、通话与 CRM 放在同一个界面里，并且通过 @ 引用互相链接，底层用 Rust 实现。它想解决的是「团队的知识被切碎在十几个 SaaS 里」这个老问题，而 AI 让这件事第一次有了可行解——不是再做一个聊天框，而是让所有对象共享同一份上下文与记忆。对 Agent 产品的启示：企业级 Agent 的竞争力往往不在模型，而在「它能不能看到足够完整的上下文」；把 CRM、邮件、文档打通之后，Agent 才能回答「这个客户上次为什么没成交」这种真正值钱的问题。做跨境贸易 Agent 时，询盘邮件、报价单、样品记录、物流节点本质上也是同一类对象图，值得用同样思路先建上下文层。

4lightpanda-io/browser 单日 +626 星：为 AI 与自动化重写的无头浏览器▸
Lightpanda 目前约 3.8 万星、1,874 个 fork，今日新增约 626 星。它不是给人类用的浏览器，而是给 AI 与自动化用的无头浏览器，用 Zig 从零实现，目标是比通用浏览器更适合大规模、长时间的自动化访问。这类项目的重要性会随着「浏览器 Agent」普及而上升：当 Agent 要替用户比价、填表、下单、查后台，浏览器就从展示层变成了执行层，启动速度、内存占用、并发密度直接决定单位任务成本。对电商与贸易 Agent 的启示很实际：抓取与操作要区分「读」和「写」，读可以用轻量无头浏览器压低成本，写则必须走官方接口或带完整审计的受控浏览器；同时要尊重站点的 AI 使用偏好与反爬规则，否则规模一上来就会撞墙。

一、今日主线（为什么选这 6 篇）

  1. 从「做对了」到「能证明」（#1、#3、#4）：AWM 让 Agent 把对未知环境的理解写成 Lean 4 证明，甚至证明「此关无解」；VeriCUA 把「任务完成」变成一次主动取证；Prefix Executability 则指出最终成功率会掩盖「中间步骤根本不可执行」。三篇合起来，是在给 Agent 评价换一套计量单位：证据与过程。
  2. RSI 开始有可结算的产出（#2）：MoLRSI 让 Agent 自己改 workflow 与模型架构、把跨任务经验存进长期记忆，在抗生素发现上把实验命中率从 8.7% 提到 15.9%。它和今天 ForgeKernel 的算子自进化、OXR 的文档解析 RSI 是同一套逻辑：先让对错可被机器验证，再让 Agent 自己找错、自己造数据、自己迭代。
  3. 真实世界会动，复现才是终局评测（#5、#6）：PAPERBENCHX 用 93 道跨 12 学科的复现任务说明，AI 科学家得先能复现已知科学；ClinGeX 则在临床基因组分析里证明，技能化编排加人类协作能把一致率从 45.7% 拉到 71.7%。再叠加今天那条「量子实验信号漂移」的自主实验室论文，核心难点是一致的：环境会变、证据会跑，Agent 必须自己发现并承认「这次不算数」。

二、每篇一句话（按阅读优先级）

  1. Algebraic World Model（arXiv，清华）：把探索写成可执行假设、再用范畴论化简成 Lean 4 模型，在 25 个 ARC-AGI-3 游戏的全部 183 关复现通关轨迹，精读。
  2. MoLRSI（arXiv，MIT / 哈佛等）：会改自己 workflow 的分子发现 Agent，抗生素筛选命中率 15.9%、8 个肽-MHC 结合物湿实验验证，精读。
  3. VeriCUA（arXiv，港大 / Google 等）：把「任务是否完成」做成主动取证，显著提升对虚假完工声明的拒绝率，选读。
  4. Prefix Executability（NeurIPS 2026，Amazon 等）：用前缀可执行性曲线与首次出错深度评价工具调用轨迹，揭示「计划条件化」带来的虚假成功率，选读。
  5. PAPERBENCHX（arXiv，复旦等）：93 道跨 12 学科论文复现任务，考核的是科学有效而非表面一致，选读。
  6. ClinGeX（arXiv，上海交大 / 新华医院等）：105 个可执行技能按依赖编排的临床基因组 Agent，223 例一致率 71.7% 对 45.7%，泛读。

三、组会讨论题

  • AWM 能证明「这一关在所有合法操作下都无解」。放到采购场景，我们能不能用同样的思路证明「这个供应商在当前规格、起订量与交期约束下不可能满足」，从而在试错超时之前就切换？要证明这件事，需要哪些可机读的约束（规格、产能、认证、账期）？
  • Prefix Executability 说：只看最终成功率，会奖励那些「计划没验证却碰巧成功」的轨迹。如果给 Accio 的询盘—比价—下单链路加一层前缀校验，哪些步骤的前置条件最值得先做（价格有效期、库存、MOQ、收货地、支付方式）？校验失败时应该重试、降级还是升级给人工？
  • MoLRSI 与 ClinGeX 都说明「技能/工作流的组织方式」比单点模型能力更决定上限。我们的 Agent 技能库该按场景切还是按能力切？当 Agent 自己改 workflow 时，谁来判断新 workflow 是否仍然合规、可解释、可回滚？
1arXiv｜Algebraic World Model：让 Agent 把未知环境写成 Lean 4 证明，还能证明「这一关无解」▸
清华团队（Guancheng Pan、Qixin Tan、Yang Yuan、姚期智）提出 Algebraic World Model。它要回答一个比「解题」更根本的问题：AI 能不能对一个完全未知的世界做严格推理？做法分四步：先在环境里探索，写出可执行的 Python 假设并不断用观测检验、修正；再把假设结构化成类型化对象与共享规则；然后用范畴论引导的变换化简结构；最后把模型形式化到 Lean 4，证明可达性与不可达性。关键结果是「不可达也能证」：在两个本就无解的游戏关卡上，AWM 构造出内核校验通过的 Lean 证明，排除了全部合法通关序列，六次运行全部成功；而配上编码工具的 Claude Opus 5.5 与 GPT-6 Astra 在 12 次基线运行里一次都没做出来。六次初始上界中有四次正确（Opus 5.5 为一次、Astra 为零次）；只告诉它「存在更便宜的获胜方式」，它就能改规则、重建证明，达到六次全对。在 25 个公开 ARC-AGI-3 游戏、183 个关卡上，这些模型让 Lean 复现全部获胜轨迹，并能预测未见过的状态转移、检测机制变化；配合 Claude Opus 5，AWM 以 99.9 分通关全部关卡，认证过的获胜轨迹只用了人类基线 43% 的动作。对 Agent 的启示：世界模型的价值不只是「预测下一个状态」，而是「能对边界下结论」；当 Agent 能证明某条路走不通，它才真正学会停止。

2arXiv｜MoLRSI：会改自己 workflow 的分子发现 Agent，抗生素实验命中率 15.9% 对专家 8.7%▸

3arXiv｜VeriCUA：把「任务完成」变成一次主动取证，拒绝 Agent 的虚假完工声明▸
计算机使用 Agent（CUA）要在桌面、移动端与网页上规模化，前提是能可靠判断任务是否真的完成——数据清洗、评测与强化学习都依赖它。现有做法各有盲区：让视觉语言模型当裁判，只能看到被提供的观测；让模型生成程序去检查应用状态，又受限于可访问的状态。两者都可能漏掉决定性证据，导致「完成」判断没有支撑。VeriCUA 把验证本身做成 Agent 的主动探索：先检查可用上下文、构造任务 rubric，再针对未解决的要求选择 GUI 检查或代码检查，最后在明确的证据规则下合并结论；同一套流程同时适用于在线与离线、不同平台与观测模态。实验里，它与参考标签的一致率优于基线，离线难例上的提升最大，在线场景对「虚假完工声明」的拒绝也更强。对 Agent 产品的启示：验收器不能只是「再看一眼截图」，而要能主动去拿证据；在电商场景里，这意味着「下单成功」不能以页面提示为准，而要以订单号、支付流水、库存扣减与商家确认四类证据交叉验证。
