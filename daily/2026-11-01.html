1苹果官宣国行 Apple 智能接入阿里千问：11 月 4 日测试、12 月随 iOS 27.3 上线，千问以「扩展」而非「替代」进入 Siri▸
10 月 31 日，苹果与阿里巴巴宣布合作，将通义千问集成进 Apple 智能：中国用户可在 Siri、写作工具与视觉智能中直接调用千问的文本与图像理解、内容生成能力，登录千问账户或使用「通过 Apple 登录」即可，无需跳转到独立 App。时间表很明确——首批功能 11 月 4 日随 iOS 开发者测试版开放，12 月随 iOS 27.3 正式推送。分工同样关键：实时翻译、照片消除、通知摘要等基础功能由苹果自研模型在端侧处理，复杂文本理解、图像识别与生成才交给云端千问；苹果把千问定义为「扩展」，驱动首批功能的仍是自家生成式模型。范围上，首批仅限 iPhone，iPad 与 Mac 需等待审批，且不包括今年 WWDC 发布的 Siri AI。阿里方面强调用户可自主选择是否开通，请求与回复不会被用于模型训练。从 2025 年 2 月蔡崇信确认合作，到 2026 年 7 月完成生成式 AI 服务备案、10 月进入进网许可，这条链路走了两年多。对做跨境 Agent 的团队，这条新闻的价值不在「谁赢了」，而在系统级入口的分工方式：基础能力端侧化、复杂能力云化、模型以可插拔扩展的形式出现——这意味着未来的分发不再只靠 App，而是靠「被操作系统调用」；同时，数据边界、备案与地区可用性会直接决定一个 Agent 能不能出现在用户面前。

2DeepSeek 公开 Super-agent 架构：Router/Worker 双层、投机执行、订阅直通，任务完成中位数 12.4 分钟▸
10 月 31 日晚，DeepSeek 发布工程实践文章《Super-agent：迈向更自主的 Agent 系统》，并开源研究原型 dsh-superagent-prototype。核心是四个特征：连续（跨会话、跨平台保留上下文）、高效（多任务并行不阻塞）、主动（观察环境并自行行动）、持久（长期在线、异常自恢复）。架构上分两层：上层 Router 接收消息、分配任务、维护全局上下文；下层 Worker 是具体执行的 Agent 会话，多个任务并行。两个设计最值得抄：一是「订阅与直通」——某个 Worker 接手 GitHub PR 后可直接订阅后续评论，新意见不再经 Router 层层转发；实验中去掉直通后，Router 决策次数增加约 30%、缓存读取 Token 增加约 37%。二是「投机执行」——发现群里在讨论 Bug 就先在后台复现、定位，找到简单修复才汇报，没结果就保持安静，避免打扰。其余机制包括两级事件过滤（程序规则筛一遍、大模型再判断）、异步 ReAct Loop（耗时任务执行时仍能响应新指令，已在 DeepSeek Harness 实现但未默认开启）、计算/状态/执行环境分离，以及独立 Watchdog 检测死循环与偏题。在约 300 条消息、20 项工作请求的模拟环境里重复 5 次，Super-agent 任务完成时间中位数 12.4 分钟、p95 为 15.7 分钟，传统单会话方案 p95 达 29.5 分钟。官方明确这是研究原型、不是产品。对 Agent 设计的启示很直接：当模型单任务能力足够强，瓶颈会转移到「人类只能同时跟进 3 到 5 个会话」；Router/Worker 加直通订阅是把注意力从人身上卸载出去的可行结构，而投机执行必须配套成本上限与静默策略，否则「主动」会变成打扰。

3Google 首次让数据中心级 TPU 在轨运行 Gemma 4：Project Suncatcher 拿到「Hello World」，2027 年试验双星互联▸
Google 10 月 30 日披露，Project Suncatcher 的原型卫星在轨完成了首次 AI 推理：地面站把提示词上行到星上的 Gemma 4 开放模型，要求写一首关于太空的俳句，卫星经过挪威斯瓦尔巴群岛上空时下传了结果——「Blue marble below / Data streams in silent grace / Starlight feeds my core.」。这颗卫星 10 月 1 日发射，随后几周完成供电、TPU 托盘上电与早期机器学习测试；本周的「Hello World」是第一次由数据中心级 TPU 在轨道上产生 AI 响应，之后还测试了太空主题的打油诗与载荷遥测问答。下一步是热应力与辐射暴露下的 TPU 可靠性测试，验证通过才谈得上 2027 年「双星互联」的里程碑。需要保持克制：一次在轨推理不等于太空数据中心商业可行，散热、辐射加固、星间带宽、发射与维护成本仍是硬约束。但它确实把「算力在哪里」变成一个新变量——当能源、散热与地理合规开始进入模型成本函数，Agent 的部署位置、数据主权与延迟预算都可能被重新定义；对跨境业务而言，这类基础设施变化值得放进长期假设，而不是当成新闻看。

1Claude 订阅改名 Max / Ultra：200 美元档取消 5 小时限制，周额度仍是 Pro 的 10 倍▸
10 月 31 日，Anthropic 调整 Claude 订阅：原来的 Max 5x 与 Max 20x 分别改名为 Max 与 Ultra，价格不变，仍是每月 100 与 200 美元。真正的变化在 Ultra：通过验证的账户不再受 5 小时窗口限制，可以在每周额度内连续使用；周额度保持 Pro 的 10 倍，同时保留新功能优先体验、Claude Code 与长程后台任务能力。Anthropic 订阅产品负责人 Mike Overell 解释了改名原因：最初「20x」指单个 5 小时窗口内是 Pro 的 20 倍，后来加入周额度，而周额度只有 10 倍，命名长期误导，他为此道歉；今年 6 月《华尔街日报》还报道过用户针对高价订阅额度宣传的诉讼。对做长程 Agent 的团队，这是一次计费范式的信号：从「窗口配额」转向「周预算 + 持续工作」，意味着产品要按任务时长、并发数与后台占用来设计预算，而不是等用户撞上限流再解释；对个人开发者，200 美元档的连续性提升，实际是在为「一直开着的 Agent」定价。

2小米开源 0.8B 的 Xiaomi-OCR-0：文档解析、字段抽取、OCR 问答三合一，Real5-OmniDocBench 95.24 第一▸
小米 10 月 31 日发布并开源 Xiaomi-OCR-0，参数只有 0.8B，基于 Qwen3.5-0.8B-Base、用约 1.7 亿条 OCR 与文档理解样本训练，把三类能力合进一个模型：文档解析（还原正文、复杂表格与公式，按阅读顺序输出 Markdown / LaTeX）、关键信息抽取（从发票、收据、卡证与业务表单直接生成 JSON 等结构）、OCR 视觉问答（围绕文档与图表做检索、计算与语义推理）。成绩上，Real5-OmniDocBench 95.24 在参与对比模型中第一；OmniDocBench v1.6 综合 96.83，总榜第二、1B 以下第一；五项主流 OCR VQA 平均 83.2，超过 8B 的 MiniCPM-V-4.5。除权重与推理代码，小米还提供浏览器 Demo、MCP 服务与 Agent Skill 工具包，并已用在小米手机与超级小爱的取餐码提取、账单记账、卡证识别、日程创建等场景。对电商 Agent 的启示：文档理解是交易链路的隐形入口——发票、装箱单、报关单、商品卡、合同，任何一处表格或公式读错，后面的工具调用就全错；0.8B 能本地跑，意味着隐私、延迟与离线可用性都有解，而「模型 + MCP + Skill」的打包方式，正在成为端侧能力交付的标准形态。

OpenAI 10 月 30 日在 API 更新日志中发布 gpt-6-rosalind，定位生命科学研究：在 GPT-6 Astra 的权重基础上做领域强化，面向生物推理与科学工具使用，覆盖化学、蛋白质工程与基因组学等长流程任务。它不是全量开放，而是走 trusted access：机构需通过资格与安全审查，进入后在 ChatGPT、Codex 与 API 中使用；配套还有可自由获取的 Codex 生命科学插件，连接 50 多个科学工具与数据库。Rosalind 系列 4 月首发、9 月转为全球符合条件机构可用，这一代把底座换到 GPT-6 Astra 并在生物基准上超过上一代。对垂直 Agent 的启示是「三层结构」：专用模型提供领域推理，工具插件负责可执行动作，准入与审计控制风险——三者缺一不可。跨境贸易里的关务、合规、原产地判定同样高风险高价值，与其让通用 Agent 硬啃，不如按这个结构做「专用模型 + 工具包 + 可审计访问」。

1OpenAI Agents API 连更五项：执行前 Auto Review、后台压缩、时间感知、会话中换工具、跨会话缓存系统提示▸

1Orkas 单日 +1,044 星：MIT 本地优先的「桌面 Agent 团队」，Commander 带队、项目记忆跨会话延续▸
Orkas 是一个 MIT 许可、本地优先的多 Agent 桌面应用：用户把目标交给 Commander，简单任务它自己完成，复杂任务则拆步骤、拉入专家 Agent，并与你已有的 Claude Code、Codex、OpenCode、OpenClaw、Hermes-Agent 协作。它用「项目」承载目标、规则、记忆与文件，新会话能接着上次继续；To-dos 把工作分给人或 Agent，Auto-advance 让团队自己认领下一项，定时自动化可按小时、天、周、月重复。所有数据留在本机，完成的工作回到你面前复核。对个人与小团队，这个形态回答了一个真实问题：Agent 不是一次性问答，而是有记忆、有分工、有节奏的持续项目；对电商运营，选品、内容、投放、客服、合规正好可以按「项目 + 角色 Agent」组织，而本地优先也缓解了商家对数据外流的顾虑。

1Google 发布 T2J-Bench：63 个整仓 PyTorch 到 JAX 迁移任务，最强 Agent 只拿到 0.676 对 0.980 的 oracle▸
Google 团队发布 T2J-Bench，专门考「整仓迁移」：63 个把 PyTorch 仓库改写成 JAX 的任务，覆盖 18 个模型家族、训练与推理两种场景，而且要求连 checkpoint 转换也不能依赖 torch，torch-free 转换本身就是交付物的一部分。评测不看单元测试通过率，也不看与参考译文的表面相似度，而是在独立的、离线、无 torch 的验证器里跑行为等价：参考结果从原始 PyTorch 冻结，候选实现必须在硬性独立性闸门下、用连续且无阈值的奖励计分，防止「偷偷 import PyTorch」伪造等价。20 组现成 Agent 与模型配置里，最强只恢复 0.676 的奖励，oracle 为 0.980；规格通过率很高，但数值与行为分歧明显。对 AI 编程的启示：真实工程里最贵的不是写新函数，而是跨范式迁移与行为对齐——框架升级、跨境系统对接、遗留代码重构都属于这一类；评测必须看整仓行为，而不是几个单测。对 Accio 这类要接商家 ERP、物流与支付系统的产品，这套「整仓等价 + 独立验证」的思路，比任何代码生成榜单都更接近真实交付。

论文要回答一个被跑分掩盖的问题：模型在进步，衡量模型的「尺子」还准吗？团队基于 117 个模型的技术报告，整理出 158 个基准、覆盖 13 个任务领域，提出 Benchmark Health Index，从三个维度打分。能力区分度看分数能否拉开模型：先以最高最低分之差的 2% 为阈值，统计超过阈值的模型对占比，再取第 10 到 90 百分位的跨度。抗饱和度不只看是否接近满分，而是按模型能力加权估计剩余提升空间，并拟合时间趋势外推 30 天，两部分按 8:2 合成。影响力不看引用量、下载量或星标，而看报告中提供有效成绩的模型，并按模型能力加权，前沿模型采用得越多分越高。合成用 CRITIC 定权：区分度 32.63%、抗饱和度 35.74%、影响力 31.63%；为避免「用某基准的成绩评价该基准」的循环，采用留一基准法（LOBO），先用其他基准估计模型能力。结果上，Humanity's Last Exam 以 67.05 排第一，Agents' Last Exam 53.08、AutomationBench 52.68 紧随其后；第四名 SWE Marathon 只差 0.59 分，但抗饱和度更高，说明「当前能区分」与「还有空间」并不同步。稳健性方面，移除抗饱和度会让平均排名变动 16.18 位、最大 82 位；随机移除 30% 的模型后，新旧排名的 Spearman 仍高于 0.97；已知饱和组与活跃前沿组的平均 BHI 分别为 0.227 与 0.600，方向与外部观察一致。这不是一篇「换个榜单」的论文，而是一套可持续更新的评测审计方法：选基准时先看它是否还能区分、是否还有空间、前沿是否还在用，再谈分数高低。

5arXiv｜Retrieval as Traversal：把记忆检索变成带成本的寻址遍历，5 token 上下文拿到 0.95 回报▸
长上下文模型反复解决高度相似的检索问题：注意力或全局检索能存很多，但每次前向都要重新找一遍；循环压缩则提前决定保留什么，之后无法反悔。两条路都没有利用一个事实——相邻检索步骤真正需要的信息往往高度重叠。论文提出把检索变成在地址空间里的持久局部遍历：记忆的内容与地址分离，效用定义为「检索到该内容所揭示的信息量」，几何只决定「到达它有多便宜」。由此得到一个带成本正则的索引目标：在局部邻域内保留信息价值，同时对每个被变得「就近可达」的记忆收费；其边际价值形式同时产生吸引与排斥压力——互补记忆在额外价值超过检索成本时应被一起取回，冗余记忆则不该仅因为各自有用就占据同一检索集合。作为原理验证，作者只在 MiniGrid Memory 上测试了最简单的固定几何实例：一个持久局部遍历头在 5 token 上下文下，用 0.59M 训练步达到 0.95 平均回报，而高斯基线需要 0.94M 步。对 Agent 记忆设计的启示：不要把所有东西塞进上下文，也不要每次全库重搜；按「信息增益 / 到达成本」组织记忆，让同一商品、同一订单、同一供应商的相关片段在邻域内可一起取回，才对得起长会话的 Token 预算。

Scaling Law 能用小实验预测大模型表现，但找到一条可靠的定律本身就需要昂贵实验。初代 SLDBench 把所有实验结果直接给 Agent，考的是拟合；v2 做了两点扩展。第一，语料从 8 个场景扩到 127 个，覆盖语言模型预训练、下游表现与视觉语言迁移，并挑出 30 个参考幂律拟合 R² 不超过 0.8 的困难场景，对应至少 1.09×10^23 FLOPs 的已报告训练算力。第二，引入主动发现：Agent 自己决定跑哪些实验、为每个实验支付记录成本（如训练 FLOPs），随着结果到来不断修正定律，最后用与被动设置相同的隐藏外推目标评分。8 个前沿 Agent 系统上，median R² 从被动的 0.72–0.75 掉到主动的 0.24–0.57，预测误差上升 1.5 到 4.7 倍；Agent 普遍偏爱便宜实验，平均只花全量成本的 8% 到 44%。低成本采购有时也能得到不错的预测，但便宜实验往往漏掉外推必需的边界条件。对 Agent 的启示：主动实验设计是一个独立能力维度，和「会不会拟合」不是一回事；对增长与定价实验同样成立——只买便宜的数据，永远不知道曲线在远处怎么弯。
