论文精选4 条

本期论文总结 · 组会分享版

一、今日主线（为什么选这 4 篇）

  1. Agent 的「内部状态」可靠性（#1 FocusGUI、#2 PAR）：一个管「每一步该看什么」（多模态感知聚焦），一个管「每一步进行到哪」（进度对齐的循环状态）。共同回答的问题是：长程多步 Agent 如何避免内部状态漂移导致的轨迹失稳——这也是今天头条里 OpenAI 披露 Astra/Sol 事件后，「Agent 状态可信」升级为行业级命题的注脚。为什么是现在：Agent 从演示走向生产，失败模式从「答错」变成「做偏」，状态可靠性成为第一瓶颈。
  2. 世界模型走向「实时可交互」（#3 Matrix-Game 4.0、#4 Ropedia W0）：从 60FPS 可玩游戏世界到跨本体机器人世界模型，视频模型正从「生成内容」转向「运行世界」，且都给出了开源/可复现的工程配方。

二、每篇一句话（按阅读优先级）

  1. FocusGUI（arXiv 2610.26203，HF 224 赞）【精读】：全模态 GUI Agent 的「聚焦感知」适配器，专治多模态流「序列干扰」，做电商操作自动化必读。
  2. PAR（arXiv 2610.27628，蚂蚁国际，HF 147 赞）【精读】：进度对齐监督让 0.5B 模型的状态跟踪外推 16×（95.5% vs CoT 0.8%），长程状态任务的训练配方。
  3. Matrix-Game 4.0（arXiv 2610.27999）【选读】：游戏引擎 + 编码 Agent + 视频渲染三层解耦，单卡 480p@60FPS 可玩游戏世界，代码权重全开源。
  4. Ropedia W0（arXiv 2610.26855）【泛读】：1 万小时人类第一视角数据预训练的跨本体「走-操」世界基础模型，具身智能的数据配方参考。

三、组会讨论题

  • FocusGUI 证明「全量喂上下文」是陷阱——我们商家工作台 Agent 的多模态输入（商品图/聊天记录/订单状态）现在是全量进 prompt 还是已有按步筛选？能否给「决策相关证据压缩」定义一个离线可评测的口径？
  • PAR 的关键是「中间状态可对齐监督」：我们哪些 Agent 任务（询盘跟进、备货补货、纠纷处理）存在天然的中间状态标注？这些任务是否更适合「循环深度 + 进度监督」而非无限加长上下文？
  • Matrix-Game 4.0 的「引擎管规则、生成管画面」分离：我们的商品 3D 展示/场景视频生成能否拆成「确定性业务引擎 + 生成式渲染」两层，让规则正确性与画面质量各自迭代？
1arXiv｜FocusGUI：全模态 GUI Agent 的「聚焦感知」适配器，专治多模态「序列干扰」（HF 224 赞）▸
NTU 等团队（arXiv 2610.26203，10 月 19 日提交，HF 当日热门第一）。针对同时接收截图、音频、视频、交互历史与设备状态的 GUI Agent，指出「每一步都全量暴露上下文」忽略了信号的相关性是稀疏且瞬态的——错误随动作反馈累积成「序列干扰」（Sequential Distraction），把 Agent 拖入不可逆的轨迹漂移。FocusGUI 用轻量适配器按当前步骤动态压缩最相关的多模态证据、注入冻结骨干的嵌入层，仅靠动作监督训练。四个全模态骨干上 Type Match 平均 +33.2、Exact Match 提升 3 倍，且不需要模态相关性标注。做 GUI Agent（含电商操作自动化、多平台店铺打理）的团队必读：注意力分配应该按步动态化，而不是均匀喂给模型。
