论文精选6 条

本期论文总结 · 组会分享版

一、今日主线（为什么选这 6 篇）

  1. Agent 的规模化规律与学习信号（#1、#5）：一篇用约 1000 名开发者与 58.5 万次任务部署回答「多买 Agent 能换多少正确率」，一篇让「预测外界」与「实际行动」共进化来提升样本效率。共同的问题：Agent 系统的性能边界由什么决定——预算结构，还是学习方式？
  2. 规模化探索与生成新范式（#2、#6）：Sky 计算团队的「发现需要遗忘」证明长程 Agent 探索必须主动丢弃工作区才能继续扩展；斯坦福的 NCM 把 VAR 的「下一尺度预测」搬进文本，用「先写概念大纲再填细节」实现 10-31 倍于扩散 LLM 的生成速度。两条路都在挑战「更多 token、更多步数」的默认扩展逻辑。
  3. 模型真的在做我们认为的事吗（#3、#4）：Nature Computational Science 的分析发现材料 LLM 主要靠「原子种类」而非「原子位置」预测物性——表面高分可能是捷径学习；GraceBench 则系统刻画 GUI Agent 的执行不稳定性。评测的效度本身成了研究对象。

二、每篇一句话（按阅读优先级）

  1. The Wealth of Agents（arXiv，Princeton 等）：第一份大规模「Agent 经济学」实测——并行人类专家预算如何换取任务正确率，做 Agent 产品容量与定价规划前必读。精读。
  2. Scaling Discovery Requires Forgetting（arXiv，斯坦福 Sky 计算）：长程 Agent 探索的规模化瓶颈在上下文堆积，「会遗忘」是扩展的前提，对长任务记忆架构设计有直接指导。精读。
  3. 材料 LLM 靠原子种类而非位置预测物性（Nature Computational Science）：AI for Science 里「高分不等于懂物理」的定量案例，警示所有用 LLM 做科学预测的场景。选读。
  4. GraceBench（arXiv）：给 GUI Agent 的「执行稳定性」立诊断基准——与电商运营、采购后台这类界面操作型 Agent 直接相关。选读。
  5. Co-Evolving Acting and Forecasting（arXiv，清华 × ServiceNow）：世界模型与策略共进化的 Agent 学习框架，RL 数据效率路线的最新样本。选读。
  6. NCM：Next-Concept Modeling（arXiv，斯坦福 Hazy Research）：文本的「先大纲后细节」粗到细生成范式，速度惊艳但规模尚小，泛读开阔思路即可。

三、组会讨论题

  • Wealth of Agents 的结论换算到跨境贸易场景：询盘响应、商品上架这类任务，多 Agent 并行的边际收益曲线长什么样？我们该在哪一点停止堆 Agent、转而优化单 Agent 质量？
  • 如果长程 Agent 必须学会「遗忘」（#2），采购/运营 Agent 的记忆该丢什么、绝不能丢什么（如合规约束）？遗忘策略要不要可审计？
  • 材料 LLM 的捷径学习与 GraceBench 的稳定性诊断共同提示：我们的 Agent 评测是否也在奖励表面指标？如何设计能区分「真会」与「看起来会」的业务评测？
