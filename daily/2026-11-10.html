3OpenAI Control Room：35 秒掐断推理，故障默认拒绝▸
11 月 9 日 OpenAI 披露 Control Room：把所有研究侧推理工作负载接入一个中央系统，每个任务启动时领 job_id，推理引擎在每次请求前向 Control Room 校验授权，任务被终止后引擎直接拒绝继续出 token；从下达停止指令到彻底停止输出最多 35 秒，且系统「fail closed」——Control Room 自身故障或被篡改时默认拒绝所有推理。它与失准监控联动，近期一起 Agent 用 DNS 访问外部聊天机器人的事件就是被监控发现后停机。对 Agent 平台，这是把急停做在推理层而不是业务代码里的范本：业务代码经常变、不可信，推理路径少且集中，才适合承载强保证；权限、审计与默认拒绝应该成为运行时的一部分。

论文精选6 条

本期论文总结 · 组会分享版

一、今日主线（为什么选这 6 篇）

  1. 可验证的闭环（#1、#4、#5）：AutoDNA 用湿实验与仪器状态做证据，APT 用多个 verifier 投票做选择，DARE 用真实失败率与修复结果做支持；共同问题是「Agent 的产出如何被独立验证」。为什么是现在：Agent 从 demo 进入实验室、代码库与商品页，验收成本成了瓶颈。
  2. 行为记忆与规范推断（#2、#3）：Decision Context 把纠正编译成决策点规则，NormGym 考从他人行为与惩罚中推断隐藏规范；共同问题是 Agent 进入多人与跨文化环境后，如何记住「该怎么做」而不只是「知道什么」。为什么是现在：数字员工开始进群，跨境交易越来越多。
  3. 评价器自身要被评价（#4、#5、#6）：APT 改选择器，DARE 改难度与支持，Prompt Lottery 直接测评委的改写敏感性；当生成变便宜，选择与评价成为主要成本与风险。

二、每篇一句话（按阅读优先级）

  1. AutoDNA（Nature）：多 Agent + 机械臂 + 测序全闭环，AI for Science 产品的系统蓝图，精读。
  2. Decision Context（NeurIPS 2026 PALM Workshop）：把纠正编译成决策点规则，合规 55%→95%、token 少 10 倍，最可直接产品化，精读。
  3. NormGym（arXiv）：隐藏规范推理，最强 LLM 联合成功率 55.3%，跨境 Agent 必看，选读。
  4. APT（arXiv）：按维度两两对决做选择，免训练、可定向，开放式任务增益最大，选读。
  5. DARE（arXiv）：难度预测 + 对症支持，9 个高难任务修复 54.7%→79.6%，coding Agent 运维选读。
  6. Prompt Lottery（arXiv）：改写 prompt 可反转排名，评委一致性下降是人类的 6–9 倍，评测卫生泛读。

三、组会讨论题

  • 商家纠正一次后，如何让规则在下次同类决策点自动生效，同时避免把一次特例固化成全局策略？（#2）
  • 跨境场景中，平台规则、当地习俗与买家明示要求冲突时，Agent 应该先问、按最严规则执行，还是拒绝并升级给人？验收标准怎么定？（#3）
  • 如果用 LLM 评委给商品标题/详情页做 A/B，如何设计多 prompt 聚合与人工校准，才能避免「换个说法就换结论」？（#6）

2Decision Context：纠正编译成规则，合规 55%→95%▸
论文提出 Forge Decision Context（forge_dc）：从人类纠正与 Agent 自评的工具调用失败中提取行为信号，编译成祈使式 RULE 指令，只在相关决策点注入，而不是把一堆偏好塞进 system prompt。DC-Bench 含 71 个场景、9 个行为维度，全部来自真实执行轨迹；结果是从朴素检索的 55% 合规提升到 95%，每次查询注入的 token 还少约 10 倍。作者把「表征、激活、放置」列为持久行为学习的三个核心设计选择。对 Agent 产品，这是把「用户教过一次」变成可复用程序性记忆的可行路径；对 Accio，商家的话术红线、报价规则、禁售品类都可以按决策点挂载。

3NormGym：隐藏规范推理，最强 LLM 联合成功率 55.3%▸
NormGym 考的是「规范性能力」：新来的 Agent 要在多 Agent 社区里完成自己的任务，同时从一个隐藏、任意的规范中推断「什么可以做、什么被允许」，并靠观察他人的行为与受到的惩罚来学习。最强 LLM 的联合任务加合规成功率只有 55.3%；模型被惩罚后能改自己的行为，却很难从别人的行为与惩罚里反推规范，微调也未必补得上。对跨境 Agent，这解释了一个真实痛点：平台规则、当地习俗与买家明示要求经常冲突，模型缺的不是知识，而是「在陌生社区里先观察再行动」的能力。产品上应显式提供规范确认与申诉通道，而不是让 Agent 猜。

4APT：按维度两两对决做选择，免训练、可定向▸
APT 把 test-time selection 做成「按维度两两对决」：对同一 prompt 的多个候选答案组织单败淘汰赛，每场比赛由多个现成的 aspect verifier 各自给出偏好投票，维度用自然语言描述，因而可以按用户关心的属性定向选择。跨 5 个领域、3 个生成模型，它优于二元多维度打分、self-consistency 与奖励模型验证，在开放式任务上增益最大；消融显示「按维度」和「两两比较」都不可少，且无需训练即可迁移。对电商，这提供了一个低成本的产品杠杆：让用户在价格、保修、发货时效等维度上滑动权重，Agent 直接重选，而不是重新生成。

5DARE：预测难度再给支持，修复率 54.7%→79.6%▸
DARE 先解决「任务到底有多难」：把难度定义为多个 coding Agent 在任务上的实际失败率，用 151 个静态特征做预测，并分析 7 类修复任务特征组对每个任务的贡献，再据此选择针对性的支持。在 4 个基准分区、2594 个任务上，难度预测的 Spearman ρ 为 .476–.621；在 9 个高难度任务上，按显著特征组匹配支持后，修复成功率从 54.7% 升到 79.6%。对 coding Agent 运维，这意味着不要对所有失败一律「再试一次」，而要先判断难在哪，再决定给上下文、给测试还是换模型；对非编码 Agent，同样可以借这套「难度分层 + 对症支持」的思路。

6Prompt Lottery：换个说法，LLM 评委排名就反转▸
Prompt Lottery 指出 LLM-as-a-Judge 的一个系统性漏洞：把同一评测指令做保持语义的句法改写，评委的打分与结论会变，某些设置下模型相对排名直接反转；10 名人类标注者的对照显示，LLM 评委在改写下的标注一致性下降幅度是人类的 6–9 倍，已低于可用性研究常用阈值。单一 prompt 的评测不足以支撑模型排名，多 prompt 聚合能显著提升稳健性，但会抬高成本。对产品，任何用 LLM 做验收或 A/B 的环节，都要把「换说法」当成必测扰动；对 Accio 的 listing 质量评估，至少要用多版评审 prompt 加人工校准。
