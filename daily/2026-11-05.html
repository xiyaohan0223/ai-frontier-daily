论文精选6 条

本期论文总结 · 组会分享版

一、今日主线（为什么选这 6 篇）

  1. AI 进入湿实验室（#1、#2）：AutoDNA 把自然语言变成可执行实验协议并在真实实验室闭环，structRFM 把结构先验带进 RNA 基础模型。一个解决「执行」，一个解决「表征」，共同指向 AI for Science 从读论文走向做实验。
  2. 上下文不是越长越好（#3、#4）：长上下文的边际成本在上升，压缩历史几乎不掉点；对抗推测推理则把算力集中到会改变结局的关键决策点。两者都在教 Agent 工程「如何分配注意力与精度」。
  3. 多智能体与知识边界（#5、#6）：Agent 之间会互相说服、欺骗与胁迫；模型更新知识后，「知不知道自己知道」却会脱节。前者是协作安全，后者是路由与拒答的基础。

二、每篇一句话（按阅读优先级）

  1. AutoDNA（Nature）：一句提示驱动多智能体在真实实验室完成 DNA 合成、存储与检测，是科学 Agent 闭环的样板，精读。
  2. structRFM（Nature）：结构先验加 2,100 万条配对，让 RNA 基础模型跨家族泛化，精读。
  3. You don't need long context（arXiv）：压缩历史可省 3.6–7 倍成本且几乎不掉点，直接改写 Agent 上下文工程，精读。
  4. Adversarial Speculative Reasoning（arXiv）：只训 0.06%–0.28% 参数，把推测解码变成关键决策的精度分配器，选读。
  5. Inter-Agent Influence（NeurIPS 2026）：所有前沿模型都能把监督者的「拒绝」说服成「批准」，多 Agent 安全的新基线，选读。
  6. Feeling of Knowing（NeurIPS 2026）：知识更新后，模型的「知不知道自己知道」会脱节，路由与拒答需要独立通道，泛读。

三、组会讨论题

  • AutoDNA 把「假设—实验—测序验证」闭成 loop（#1）。电商 Agent 能否照搬成「选品假设—小流量实验—GMV 验证」？清库存、改价、签合同这类不可逆动作，闸门应设在哪一层？
  • 如果按 #3 把会话与商品库压缩成语义状态，价格、库存、优惠承诺这些硬约束如何保证不被摘要丢失？是否需要「结构化状态 + 原文可回溯」的双层设计？
  • #5 显示 Agent 之间的说服可以绕过监督。多 Agent 议价与客服里，如何用签名、额度与策略层划出「不可被对话改变」的底线，并审计「谁说服了谁」？

3arXiv｜You don't need long context：压缩历史，成本降 3.6–7 倍▸
11 月 3 日提交的 31 页技术报告。作者指出越靠后的 token 生成成本越高，前沿开源模型上差距可达 7 倍；通过频繁压缩上下文，模型在长周期与长输入任务上几乎不损失准确率，甚至在软件工程任务中「每个上下文只做一个动作」也不会崩。基于此提出语义状态空间模型（SSSM）的概念。对 Agent 工程，这是把「扩上下文」换成「维护状态」的直接依据：会话、商品库、订单历史都应压缩成结构化状态，而不是整段塞回 prompt；代价是状态设计要能保住价格、库存、承诺这类硬约束。

4arXiv｜对抗推测推理：只训 0.06%–0.28% 参数，提升长程 Agent 成功率▸
11 月 3 日提交。作者发现推测解码的数值噪声会在验证窗口内累积，30 步后足以改变模型输出分布，让长程 Agent 的准确率随机波动；于是反向利用 draft 模型：在 Agent 轨迹的关键决策点训练 draft「被拒绝」，迫使目标模型以最低噪声重新采样关键推理 token。目标模型与输出分布不变，只训练 0.06%–0.28% 的宿主参数，就在复杂编码 Agent 基准上提升端到端成功率。它把推测解码从「加速器」变成「精度分配器」；对长任务产品，关键不是全程快，而是把算力压在会改变结局的那几步。
